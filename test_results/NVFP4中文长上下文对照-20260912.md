# NVFP4 中文长上下文对照（2026-09-12）

## 测试口径

- 硬件：2× RTX 2080 Ti 22GB，TP=2，并发=1
- 中文输入：精确 65,536 / 131,072 / 204,800 token
- 输出：固定 128 token，`temperature=0`，关闭思考
- KV Cache：FP8；前缀缓存关闭或使用全新进程的首次请求
- v0.2 NVFP4、FastLLM NVFP4 均开启 MTP3
- DFlash 使用 FP8 主模型与官方 DFlash2 draft 模型，分别测试 draft 3 / 5 / 7
- 每点单次实跑；长上下文结果不等同于三次中位数

## 结论

1. **长输入端到端首选 FastLLM NVFP4 MTP3。**  
   它在三档上下文中都取得最高 Prefill 和最低总耗时。相对 v0.2，64K、128K、
   200K 总耗时分别减少约 46.6%、4.6%、6.0%。

2. **只看长上下文 Decode，v0.2 更稳定。**  
   v0.2 在 64K、200K 分别达到 55.07、50.01 tok/s；FastLLM NVFP4 在
   200K 降至 27.62 tok/s。v0.2 记录到的 MTP 平均接受率约为 67.5%、
   62.9%、69.9%。FastLLM 当前接口没有输出可直接对齐的接受率指标。

3. **DFlash7 整体优于 DFlash3/5。**  
   DFlash5 在 64K Decode 略高于 DFlash7（53.88 vs 53.62），但差距仅 0.5%；
   到 128K、200K，DFlash7 分别领先 DFlash5 4.2%、14.4%。DFlash7 是仓库推荐
   的 block size 8（7 个 draft token），DFlash5 仅为实验参数。

4. **DFlash 不是纯 NVFP4 对照。**  
   三组 DFlash 使用 FP8 主模型；因此可比较实际服务速度，但不能把差异全部归因于
   MTP 与 DFlash 算法。
