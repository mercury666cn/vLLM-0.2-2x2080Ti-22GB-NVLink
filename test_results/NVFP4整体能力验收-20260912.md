# NVFP4 整体能力验收（2026-09-12）

## 结论

**本轮不切生产。** NVFP4 的综合等权得分达到 FP8 的 **100.44%**，超过已调整的
90% 门槛；但长上下文类别比 FP8 低 **6.78 个百分点**，超过单项最多退化 3 个
百分点的门槛，因此最终生产门禁未通过。

NVFP4 仍保留为 `:8001` 候选服务，`:8000` 不启用。它的速度优势是真实的，但目前
不能把“更快”解释成 128K/200K 检索质量也同样可靠。

## 测试口径

- 运行时：同一 `native/fastllm:official-wheel`，ftllm 0.1.8.2
- 模式：FP8 与 NVFP4 都使用 MTP3、FP8 KV、210K 上下文、并发 1
- 固定题集：849 个场景，温度 0，题序和参数一致
- 代码题：HumanEval 164 题，在断网、限 CPU/内存的一次性容器中执行
- 评分门槛：综合不低于 FP8 的 90%；任一类别退化不超过 3pp；稳定性通过

## 最终得分

| 类别 | FP8 | NVFP4 | NVFP4 - FP8 |
|---|---:|---:|---:|
| 中文知识（C-Eval + CMMLU） | 33.50% | 42.00% | +8.50pp |
| 数学推理（GSM8K + MATH-500） | 69.50% | 70.50% | +1.00pp |
| 代码（HumanEval pass@1） | 65.24%（107/164） | 65.24%（107/164） | 0.00pp |
| 指令遵循（IFEval） | 75.00% | 73.56% | -1.44pp |
| 长上下文 | 45.72% | 38.95% | **-6.78pp** |
| 多轮严格 JSON 状态保持 | 0.00% | 0.00% | 0.00pp |
| 六类等权综合 | **48.16%** | **48.37%** | +0.21pp |

综合比值：`48.37 / 48.16 = 100.44%`。两组 bootstrap 95% 区间高度重叠，
所以中文知识的表面领先不能证明 NVFP4 真正“变聪明”；可靠结论是整体能力未见
系统性下降，但长上下文检索存在明确风险。

多轮项的绝对分为零，是因为模型经常把要求保留的完整负责人值缩写，或自行改写
严格 JSON 键名。它对 FP8/NVFP4 的相对比较公平，但也说明当前提示模板不适合把
严格状态记忆作为生产保证。

## 长上下文复核

首轮 15 组多针检索：

- FP8：12/15
- NVFP4：7/15

由于首轮差距接近单项门槛，按计划在全新、稳定的 NVFP4 进程中复跑全部 15 组：

- NVFP4 复跑：**4/15**
- 64K：3/5
- 128K：0/5
- 200K：1/5

生产冒烟中的单个固定针在 200K 可以命中，但这不能替代多位置、多针测试。当前
证据表明 NVFP4 的长文“容量能装下”，不等于信息检索稳定性与 FP8 相同。

## CPU 是否值得更换

FP8 有效推理采样共 6022 点：

- 推理进程平均使用约 4.46 个 CPU 核，P95 约 4.52 核
- 折算整机 CPU 平均 6.19%，P95 6.28%，最大 7.04%
- GPU0 平均利用率 94.35%，GPU1 平均 89.16%
- 系统 load 平均 4.52，远低于 72 逻辑线程

结论：**当前单并发无需换 CPU。** 推理明显由 GPU/内核主导。换新 CPU 可能改善
分词和请求调度，但不会给当前 decode 带来明显提升；只有未来提高并发或把大量
预处理搬到本机时才值得重评。

## 门禁判定

- 题集完整：通过（849/849，两模型均无最终 API 错误）
- 综合 ≥ FP8 90%：通过（100.44%）
- 单项退化 ≤ 3pp：**失败**（长上下文 -6.78pp）
- 最终生产门禁：**失败**
